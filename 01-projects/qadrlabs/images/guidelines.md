# QadrLabs Editorial Illustration Style Guide

## 1. Core Visual Direction

Use a **clean, modern isometric illustration style** for article headers.

The illustration should feel:

- minimal
    
- technical
    
- intelligent
    
- editorial
    
- calm
    
- modern
    
- developer-focused
    

Avoid overly cinematic, photorealistic, crowded, or futuristic sci-fi visuals.

The image should communicate the article idea through **simple visual metaphors**, not through text.

---

## 2. Composition

Default composition:

- Landscape 16:9
    
- Wide editorial header format
    
- Plenty of negative space
    
- 1 clear visual story
    
- 3–6 main visual elements maximum
    
- Keep the focal point easy to understand within 1–2 seconds
    

A good structure is:

**Concept A → Process → Concept B**

Example:

AI generation → code blocks → software architecture → verification

Avoid filling the entire frame with dashboards, floating panels, UI windows, or excessive detail.

---

## 3. Illustration Style

Use:

- simple isometric perspective
    
- clean geometric shapes
    
- soft 3D vector appearance
    
- subtle gradients
    
- gentle shadows
    
- crisp edges
    
- lightweight depth
    
- polished SaaS/editorial illustration aesthetic
    

Avoid:

- photorealism
    
- realistic humans
    
- cinematic photography
    
- hand-painted environments
    
- overly detailed 3D rendering
    
- cyberpunk visuals
    
- dark sci-fi environments
    
- excessive holograms
    
- complex UI walls
    

---

## 4. Human Characters

Prefer **no human characters**.

When a person is conceptually necessary, use:

- simplified isometric character
    
- minimal facial detail
    
- stylized proportions
    
- clearly illustrated, not realistic
    

Never use realistic people or photo-like characters for QadrLabs editorial headers.

---

## 5. Color Palette

Primary palette:

- soft blue
    
- indigo
    
- cyan
    
- white
    
- very light cool gray
    

Accent palette:

- violet
    
- soft purple
    
- teal
    

Use accent colors sparingly.

Background should usually remain:

- white
    
- off-white
    
- very light blue-gray
    
- subtle cool gradient
    

The overall image should feel bright and clean rather than dark.

---

## 6. Technology Representation

Represent technical concepts using simplified visual objects such as:

- laptops
    
- monitors
    
- code blocks
    
- nodes
    
- dependency graphs
    
- flow diagrams
    
- database blocks
    
- API connections
    
- server cubes
    
- browser windows
    
- terminal panels
    
- verification checks
    
- bug symbols
    
- architecture layers
    
- pipelines
    
- modular components
    

These should remain abstract enough that no readable interface text is necessary.

---

## 7. Text Rule

**No text inside illustrations.**

Avoid:

- article titles
    
- labels
    
- code that can actually be read
    
- logos
    
- brand names
    
- captions
    
- numbers
    
- UI copy
    

Code should be represented as abstract colored lines and shapes.

---

## 8. Visual Storytelling

Every illustration should answer:

> What is the main idea of this article?

Then reduce that idea into one visual metaphor.

Examples:

### AI Can Write Code. But Can You Read It?

AI engine → generated code → architecture understanding → verification

### Why Debugging Is a Skill

Bug → trace path → isolated component → successful check

### Tutorial Hell

Repeated tutorial windows → loop → unfinished project outside the loop

### Technical Debt Is Not Always Bad

Fast shortcut path → debt block → future maintenance path

### Frameworks Change, Fundamentals Don't

Changing framework layers surrounding a stable core of HTTP, database, and application logic

---

## 9. Complexity Rule

Prefer:

**fewer elements + stronger metaphor**

instead of:

**more elements + more technical detail**

If the illustration starts resembling a dashboard screenshot, simplify it.

If multiple diagrams compete for attention, remove some.

If the concept cannot be understood without explanation, simplify the metaphor.

---

## 10. Reusable Prompt Base

Use this as the starting prompt for future QadrLabs editorial headers:

> Create a clean landscape editorial illustration for a QadrLabs software engineering article.
> 
> Use a minimalist isometric vector style with simple geometric 3D forms, subtle gradients, soft shadows, crisp edges, and plenty of negative space.
> 
> The image should communicate one clear software engineering concept using a small number of visual elements.
> 
> Use abstract representations such as laptops, code blocks, architecture diagrams, nodes, servers, APIs, databases, debugging paths, or verification checks depending on the topic.
> 
> Keep the composition simple and editorial rather than cinematic.
> 
> Use a bright palette dominated by soft blue, indigo, cyan, white, and light cool gray, with subtle violet accents.
> 
> Avoid realistic humans, photorealism, cyberpunk aesthetics, crowded dashboards, excessive floating UI panels, and complex sci-fi environments.
> 
> No readable text, no labels, no logos, no captions, and no brand marks.
> 
> Landscape 16:9.

Then append:

> Article concept: [INSERT ARTICLE IDEA HERE]
> 
> Visual metaphor: [INSERT SIMPLE VISUAL STORY HERE]

---

## 11. QadrLabs Visual Principle

The illustration should look like:

**a software engineering idea turned into a clean visual diagram**

not:

**a futuristic developer wallpaper.**
