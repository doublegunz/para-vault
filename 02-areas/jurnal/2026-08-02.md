# Prompt Implementasi Simple LMS

Lanjutkan implementasi Simple LMS di repository ini menggunakan gated workflow yang sudah disetujui.

## Sumber Kebenaran

Baca seluruh file berikut sebelum mengubah kode:

1. `AGENTS.md`
2. `docs/ideas/simple-lms.md`
3. `docs/specs/simple-lms.md`
4. `tasks/plan.md`
5. `tasks/todo.md`

Spesifikasi, plan, task checklist, dan dependency gate telah disetujui. Task 1 dan Task 2 telah diimplementasikan serta diverifikasi; pertahankan perubahan tersebut dan jangan mengulanginya. Jangan mengubah requirement atau memperluas scope tanpa memperbarui spesifikasi dan meminta persetujuan terlebih dahulu.

## Cara Memulai

1. Periksa `git status` dan pertahankan semua perubahan yang sudah ada.
2. Temukan task bernomor paling kecil di `tasks/todo.md` yang belum selesai.
3. Pastikan Task 1 dan Task 2 sudah selesai beserta seluruh verification-nya, lalu mulai hanya dari **Task 3: Activate verified accounts with a stored locale**.
4. Kerjakan tepat satu task dalam satu giliran. Jangan mengerjakan task berikutnya secara otomatis.
5. Setelah task selesai, berikan hasil untuk review dan tunggu persetujuan sebelum melanjutkan.

## Workflow Wajib

- Aktifkan skill yang relevan sebelum bekerja. Untuk implementasi gunakan minimal:
  - `context-engineering` untuk memuat konteks task secara terbatas;
  - `incremental-implementation` untuk menjaga perubahan tetap kecil;
  - `test-driven-development` untuk mengerjakan behavior melalui failing test terlebih dahulu;
  - `laravel-best-practices` untuk setiap perubahan Laravel/PHP;
  - `pest-testing` untuk setiap test Pest;
  - `git-workflow-and-versioning` untuk menjaga scope perubahan;
  - `authorization-development` untuk role, permission, policy, capability, atau protected route;
  - `fortify-development` untuk registration, verification, login, 2FA, atau passkey;
  - `inertia-react-development`, `wayfinder-development`, `frontend-ui-engineering`, dan `tailwindcss-development` ketika task menyentuh frontend terkait.
- Gunakan Laravel Boost `application-info` pada awal sesi dan `search-docs` sebelum setiap perubahan Laravel, Fortify, Inertia, Pest, atau Tailwind yang version-sensitive.
- Ikuti convention file yang sudah ada. Periksa sibling file sebelum membuat atau mengedit file.
- Gunakan `php artisan make:* --no-interaction` untuk membuat class, model, migration, controller, request, policy, dan test Laravel.
- Gunakan Wayfinder untuk seluruh link dan form frontend. Jangan mengedit file Wayfinder yang dihasilkan.
- Backend policy, gate, middleware, atau controller authorization adalah security boundary. Menyembunyikan UI tidak cukup.
- Jangan menambahkan dependency selain yang telah disetujui di `tasks/todo.md`.
- Dependency rich-text hanya boleh diinstal pada Task 17 dengan perintah yang tercantum di Dependency Approval Gate.
- Jangan mengimplementasikan JWT/SSO, self-enrollment, mandatory lesson sequencing, mobile app, atau fitur lain yang ditandai out of scope.
- Jangan membuat commit kecuali pengguna memintanya.
- Jangan menggunakan sub-agent kecuali pengguna secara eksplisit meminta delegasi atau parallel agent work.

## Siklus Satu Task

Untuk task yang dipilih:

1. Baca deskripsi, acceptance criteria, dependencies, file, dan verification pada task tersebut.
2. Pastikan seluruh dependency task sudah selesai. Jika belum, berhenti dan laporkan dependency yang belum terpenuhi.
3. Periksa bagian spesifikasi yang terkait dan source code yang benar-benar diperlukan saja.
4. Gunakan dokumentasi resmi/version-specific untuk keputusan framework atau library.
5. Tulis failing Pest test terkecil yang membuktikan behavior atau authorization boundary.
6. Jalankan test tersebut dan pastikan gagal karena behavior memang belum tersedia.
7. Implementasikan perubahan minimum agar test lulus.
8. Jalankan focused test, formatter, static analysis, dan frontend checks yang diwajibkan task.
9. Bila task mempunyai UI, verifikasi di browser nyata: allowed/forbidden role, responsive layout, keyboard access, console, dan network errors.
10. Review diff untuk memastikan tidak ada perubahan di luar scope atau secret.
11. Centang acceptance criteria dan verification di `tasks/todo.md` hanya jika benar-benar terbukti.
12. Jika seluruh bagian task selesai, centang judul/status task yang relevan dan laporkan bukti verifikasi.
13. Berhenti setelah satu task. Jangan memulai task selanjutnya sebelum pengguna menyetujuinya.

## Aturan Checkpoint

Jika task yang selesai merupakan task terakhir sebelum Checkpoint A, B, C, D, atau E:

- Jalankan seluruh verification pada checkpoint.
- Jangan menandai checkpoint selesai bila browser verification atau quality gate masih tertunda.
- Laporkan kegagalan secara jujur dan kembalikan koreksi ke task pemilik terkecil.
- Tunggu persetujuan pengguna sebelum memasuki fase berikutnya.

## Definition of Done per Task

Sebuah task hanya selesai jika:

- seluruh acceptance criteria terbukti;
- focused test lulus;
- authorization allowed, forbidden, guest, dan unverified tercakup bila relevan;
- PHP yang berubah telah diformat dengan `vendor/bin/pint --dirty --format agent`;
- static analysis dan frontend quality gates yang relevan lulus;
- browser verification selesai bila task memiliki UI;
- `tasks/todo.md` diperbarui sesuai bukti aktual;
- tidak ada dependency, scope, atau destructive action yang tidak disetujui.

## Instruksi untuk Giliran Berikutnya

Mulai hanya dari **Task 3: Activate verified accounts with a stored locale**. Sebelum mengubah kode, pastikan Task 1 dan Task 2 telah ditandai selesai beserta bukti verification-nya dan seluruh dependency Task 3 terpenuhi. Sampaikan commentary singkat, aktifkan skill yang diwajibkan, baca konteks Task 3 secara terbatas, gunakan Laravel Boost `application-info` pada awal sesi dan `search-docs` sebelum perubahan version-sensitive, lalu kerjakan Task 3 secara test-driven. Setelah Task 3 terverifikasi, berhenti dan serahkan hasil untuk review pengguna; jangan mulai Task 4.
